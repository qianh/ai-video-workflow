# ADR-004：插件隔离级别

> 状态：已决策，M1 预留 / M3 适配器落地  
> 日期：2026-07-25  
> 关联计划：M1-09；M3 适配器；AWAP

## 背景

工作站需接入 Codex、Grok、FFmpeg、music-downloader 及未来第三方能力。若在 sidecar 主解释器 `import` 第三方代码：

- 崩溃拖垮整应用
- 权限与依赖互相污染
- 难以审计“谁写了哪里”

## 决策

1. **V1 插件 / 适配器一律独立子进程**  
   不在 sidecar 主解释器执行第三方 Python 包体逻辑。
2. **协议**：与核心相同的能力契约（AWAP / 受控 CLI wrapper），结果经文件 + 清单回传。
3. **权限清单**（安装或启用时展示）：
   - 可读输入路径集合
   - 可写输出/暂存目录
   - 允许的环境变量名（非全量继承）
   - 是否允许浏览器 Cookie / 付费 API
   - 超时、最大输出、并发上限
4. **环境注入**：只注入声明变量；禁止把父进程完整 `environ` 拷给插件。
5. **可执行路径**：由设备发现或内置组件表提供，**用户输入不能指定任意可执行文件路径**。
6. **失败边界**：插件崩溃只失败当前任务；sidecar 与 UI 保持可用。

## 证据与依据

- 架构 §13.4 插件机制、§11.2 环境安全
- M0 外部能力均以 CLI 子进程探测（Codex / Grok / FFmpeg / music-downloader）
- music-downloader Cookie 重试必须用户授权（M0-09）

## 替代方案

### 同进程 Python 插件 API

集成成本低，隔离差，一个原生扩展即可弄崩进程。不采用。

### WASM 插件沙箱

隔离强，但 FFmpeg/本地模型/CLI 生态不适配。V1 不采用。

### 仅 Shell 字符串拼接调用

注入与日志泄露风险高。禁止；统一参数数组调用。

## 影响

- 每个适配器需要清单 Schema 与合规测试（见 ADAPTER_PROTOCOL）
- 核心 sidecar 保持“编排 + 领域 + 仓储”，重活在外
- 诊断包记录适配器版本、权限摘要与脱敏命令

## 回退

1. 某适配器不稳定 → 禁用该能力，不卸载核心  
2. 需要更高隔离 → 再评估容器/虚拟化（非 V1）  

## 后续验证

- 取消后无残留子进程  
- 输出路径逃逸测试  
- 未声明环境变量不会被注入
