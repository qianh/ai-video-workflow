# ADR-005：全局资产导入策略

> 状态：已决策，M1 文件层落地  
> 日期：2026-07-25  
> 关联计划：M1-06；全局素材库；music-downloader 导入

## 背景

存在两类素材：

- **全局库**：跨项目复用（音色、角色定妆、音乐等）
- **项目资产**：某剧集生产使用的正式引用

若项目只保存“指向全局库的绝对路径”，全局库移动/外置盘拔出/清理会导致项目损坏。

## 决策

采用 **“导入项目”** 策略：

1. 全局资产被项目采用时：
   - 在 `project.db` 创建业务引用（`AssetFile` 等）
   - 将字节落入项目目录树（`assets/...`）
2. **优先硬链接**（同卷、支持时），否则 **复制**
3. 外置磁盘或不支持硬链接的文件系统 → 强制复制
4. 项目 **不得** 依赖全局库中可移动的裸绝对路径作为唯一事实
5. 库内路径一律 **相对项目根**；解析后必须仍在项目根或批准的外置媒体根内
6. 外部下载（如 music-downloader）先入 **任务暂存**，校验后原子移动到项目 `assets/`，授权默认 `pending`

### 文件提交协议（所有外部生成/下载）

1. 任务唯一暂存目录  
2. CLI 只能写该目录  
3. FFprobe / MIME / 尺寸 / 时长 / 哈希校验  
4. 原子移动到最终目录  
5. 短事务登记数据库  
6. 事务失败留下可识别孤儿文件，供清理建议（不自动删除）

## 证据与依据

- 架构 §10 项目文件系统与全局资产引用  
- M0-09：强制 `--output` 暂存，禁止默认 `~/Music/Downloads`  
- M0-05：Grok 媒体必须从 session 目录复制到任务目录  

## 替代方案

### 仅引用全局路径（不复制）

省空间，项目脆弱。不作为默认；可选“链接模式”若未来需要，也必须可检测失效。

### 一律复制

实现简单，磁盘占用大。作为硬链接失败时的回退，而非唯一策略。

### 内容寻址全局 CAS + 项目符号链接

优雅但实现与迁移成本高。V1 后评估。

## 影响

- 项目可整体搬家（相对路径）
- 导入会占用磁盘；UI 需显示复制/硬链接结果
- 清理全局库不会静默破坏已导入项目
- 未确认外部音乐不得进发布母版

## 回退

1. 硬链接异常 → 自动复制并记录  
2. 磁盘不足 → 导入失败，不写半截业务引用  
3. 用户明确要求“仅引用” → 需单独产品开关与失效检测（非 V1 默认）  

## 后续验证（M1）

- 项目移动后仍可打开  
- 跨卷导入走复制  
- 暂存失败不污染 `assets/`
